# GetMcapToCsv 利用マニュアル

走行データ（mcap）から、**車両ID と時間帯を指定して CSV を取り出す**ためのツールです。
このマニュアルは初めて使う人向けに、**上から順番に進めれば CSV が手に入る**構成に
なっています。細かい話・エラー対処は最後の「[9. トラブルシューティング](#9-トラブルシューティング)」に
まとめてあるので、途中で詰まったらそこを見てください。

> より詳しい技術情報は [README.md](../README.md)（CLI の全オプション）と
> [GCP_EXECUTION.md](GCP_EXECUTION.md)（VM 運用の詳細・コスト内訳）にあります。

## 1. このツールでできること

- GCS バケット `t2-ft-original-data` にある走行データ mcap から、
  **車両ID・日付・時間帯・トピック・カラム**を指定して CSV を抽出する
- ブラウザ UI で「検索 → ファイル確認 → トピック選択 → 出力」を順に操作できる
- CSV のほか、**時間帯・トピックで切り出した mcap** や **元 mcap そのもの**の取得も可能
- 手元に保存済みのローカル mcap の CSV 化にも対応

出力される CSV の先頭 3 列は共通です:

| 列 | 内容 |
|----|------|
| `time_jst` | `MM/DD HH:MM:SS.mmm`（日本時間） |
| `t_sec` | 抽出範囲先頭からの経過秒 |
| `t_ns` | 元のタイムスタンプ（ナノ秒, epoch） |

## 2. 最初に知っておくこと（お金の話）

GCS からファイルをダウンロードすると **約 18 円/GB** の通信課金（egress）がかかります。
走行データの mcap は大きい（1 回の抽出対象で数 GB になることも）ため、
mcap を PC にダウンロードして変換すると**そのぶん課金されます**。
トピックやカラムを絞ってもダウンロード量はほぼ減りません（mcap の構造上の制約です）。

そこでこのツールでは、CSV 抽出の**推奨ルートを「VM 経由」**にしています:

```
直接ルート:  GCS ──[ mcap 数GB / 数十〜数百円 ]──> 手元PC ──変換──> CSV
VM 経由:    GCS ──[ mcap / ¥0 ]──> GCP内のVM ──変換──> CSV ──[ 数MB / ほぼ¥0 ]──> 手元PC
```

VM 経由なら mcap は GCP の中から出ないので通信課金がほぼ 0 になり、
かかるのは VM の稼働費だけ（**1 回あたり ¥5〜10 程度**。使い終わると VM は自動削除され、
待機費も 0 円）です。UI のボタン 1 つで VM の作成から削除まで自動で行われるので、
**VM やインフラの知識は不要**です。

> 検索・トピック一覧・カラム一覧などの操作で読むのはメタデータ数 MB だけ
> （1 回あたり 1 円未満）なので、気にせず操作して大丈夫です。

## 3. 初回セットアップ（最初の 1 回だけ）

Windows + PowerShell を前提に書きます（Mac/Linux の場合の違いは各所に注記）。

### 3-1. 必要なものをインストールする

以下が PC に入っている必要があります。無ければインストールしてください。

| ソフト | 用途 | 入手先 |
|--------|------|--------|
| Python 3.10 以上 | ツール本体の実行 | https://www.python.org/downloads/ |
| gcloud CLI | GCP（データ置き場）へのアクセス | https://cloud.google.com/sdk/docs/install |
| git | リポジトリ・社内パッケージの取得 | https://git-scm.com/downloads |

> **git について**: ツール一式を **zip で受け取った場合は git は不要**です
> （→ [3-2 の B](#3-2-このツールを入手して依存パッケージを入れる)）。
> GitHub から自分で取得する場合のみ必要です。

#### Python のインストール手順（Windows）

1. https://www.python.org/downloads/ を開き、黄色の「Download Python 3.x.x」を
   クリックしてインストーラをダウンロード
2. インストーラを実行。**最初の画面で必ず「Add python.exe to PATH」にチェック**を
   入れてから「Install Now」を押す（このチェックを忘れると後の手順でコマンドが
   見つからずエラーになります。忘れた場合は一度アンインストールしてやり直すのが早い）
3. 確認: **新しく** PowerShell を開いて次を実行し、バージョンが表示されれば OK
   ```powershell
   python --version
   ```
   `Python` とだけ表示されて Microsoft Store が開いてしまう場合は、
   「設定 → アプリ → アプリ実行エイリアス」で `python.exe` / `python3.exe` をオフにする

#### gcloud CLI のインストール手順（Windows）

1. https://cloud.google.com/sdk/docs/install を開き、Windows 用インストーラ
   （`GoogleCloudSDKInstaller.exe`）をダウンロードして実行
2. 選択肢は**すべて既定のまま**「Next」で進めてよい
3. 完了画面に「Run `gcloud init`」等のチェックが出たら、**チェックを外して**終了してよい
   （初期化は不要。このツールで使うログインは [3-4](#3-4-gcp-にログインする) で行います）
4. 確認: **新しく** PowerShell を開いて次を実行し、バージョンが表示されれば OK
   ```powershell
   gcloud --version
   ```

> どちらも「コマンドが見つからない」と出る場合は、インストール後に**新しく開いた**
> PowerShell で実行しているかを確認してください（PATH は開き直さないと反映されません）。

また、GCP 側の**権限**として以下が必要です。無い場合は GCP 管理者に依頼してください
（依頼文の例は [9-2](#9-2-権限がない系のエラー) 参照）:

- バケット `t2-ft-original-data` の読み取り権限（自分の Google アカウントに対して）
- VM 経由ルートを使う場合: プロジェクト **`t2-integration`** で VM を作れる権限
  （`roles/compute.instanceAdmin.v1`。このツールでは t2-integration に VM を作る運用が
  標準です。権限が無い場合の代替は [9-2](#9-2-権限がない系のエラー)）

### 3-2. このツールを入手して依存パッケージを入れる

入手方法は 2 つあります。どちらか一方でよいです。

**A. GitHub から取得する（git が必要）**

```powershell
git clone https://github.com/Shintaro-Hirata/GetMcapToCsv.git
cd GetMcapToCsv
```

**B. zip で受け取った場合（git 不要）**

配布された zip を好きな場所（例: デスクトップ）に**展開するだけ**です。
zip に `mcap-ros2idl-support` フォルダが同梱されていれば、
**次の 3-3（zero-plotter の取得）も丸ごと不要**になります。

> 同梱版の注意: `mcap-ros2idl-support` は更新され続けているパッケージなので、
> 将来「一部のトピックだけ 0 行」（→ [9-4](#9-4-抽出結果が-0-行空になる)）が出たら、
> 配布元に新しい zip をもらってください（同梱版は `git pull` での自己更新ができません）。

**共通: 依存パッケージのインストール**

エクスプローラで **`install_deps.bat` をダブルクリック**します。
zip 版で `mcap-ros2idl-support` が同梱されている場合は自動で検出され、
git なしでインストールされます。

> A の場合に `mcap-ros2idl-support` の行でエラーになったときは、次の 3-3 で
> 手動インストールできるので、ここでは先に進んで構いません。

### 3-3. zero-plotter（デコード用パッケージ）を用意する

> **zip 配布で `mcap-ros2idl-support` が同梱されていた場合、この手順は不要です。**
> [3-5](#3-5-vm-経由ルートの設定ファイルを作る) の `ROS2IDL_LOCAL_PATH` には
> 同梱フォルダ（`GetMcapToCsv\mcap-ros2idl-support`）のフルパスを指定してください。

`/t2/*` トピックのデコードには社内パッケージ `mcap-ros2idl-support`
（zero-plotter リポジトリの一部）が必要です。**好きな場所に clone** してください:

```powershell
cd C:\Users\<自分>\Desktop\Dev    # 好きな場所でOK
git clone -b yatagarasu/main https://github.com/t2-auto/zero-plotter.git
```

3-2 で `mcap-ros2idl-support` のインストールに失敗していた場合は、続けて:

```powershell
pip install .\zero-plotter\mcap-ros2idl-support
```

> **重要**: このパッケージは更新され続けています。特に `/t2/main_mabx/*` などの
> apex_json 形式トピックは**新しい版でないとデコードできません**。
> 「トピック名は出るのに中身が 0 行」になったら、まず
> `cd zero-plotter && git pull` で更新してください（→ [9-4](#9-4-抽出結果が-0-行空になる)）。

### 3-4. GCP にログインする

PowerShell（またはターミナル）で次の 2 つを実行します。それぞれブラウザが開くので、
**会社の Google アカウント**でログインしてください。

```powershell
gcloud auth login                          # gcloud コマンド用
gcloud auth application-default login      # ツールがデータを読むときの認証 (ADC)
```

> この 2 つのログインには**有効期限があり、日をまたぐと切れます**（会社のセキュリティ
> ポリシーによるもので正常な動作です）。期限が切れた状態で抽出を実行すると、UI が
> 自動的に再ログインの画面を開くので、ブラウザでログインし直せばそのまま続行されます
> （→ [9-2](#9-2-権限がない系のエラー)）。

### 3-5. VM 経由ルートの設定ファイルを作る

CSV 抽出の推奨ルート「VM 経由」を使うための設定です（初回のみ）。

```powershell
Copy-Item scripts\gcp.env.example scripts\gcp.env
```

作成された `scripts/gcp.env` をメモ帳等で開き、次の 4 つを確認・記入します
（自分で書くのは実質 `GCP_VM` と `ROS2IDL_LOCAL_PATH` の 2 つだけです）:

| 設定 | 何を書くか |
|------|-----------|
| `GCP_PROJECT` | **`t2-integration` のままでよい**（社内標準。ここで VM 作成の権限エラーが出る場合は → [9-2](#9-2-権限がない系のエラー)） |
| `GCP_ZONE` | `asia-northeast1-a` のままでよい（データと同じ東京リージョン） |
| `GCP_VM` | VM の名前。**人ごとに別の名前**にする（例: `mcap-worker-yamada`。同名だと他の人と同時実行したとき衝突します） |
| `ROS2IDL_LOCAL_PATH` | 3-3 で clone した中の `zero-plotter/mcap-ros2idl-support` フォルダのフルパス（zip 配布の同梱版なら `GetMcapToCsv\mcap-ros2idl-support` のフルパス） |

さらに、コストを最小にしたい場合は `SPOT=1` の行のコメント（先頭の `#`）を外すのが
おすすめです（VM 稼働費が約 1/3 に。まれに実行が中断されますが、再実行すれば済みます
→ [9-3](#9-3-vm-経由の抽出が途中で失敗する)）。

これで初回セットアップは完了です。

## 5. CSV を取り出す（毎回の基本手順）

UI は上から「① 検索条件 → ② 対象ファイル → ③ トピック選択 → ④ 出力」の順に
並んでいます。そのまま上から進めます。

### ① 検索条件を入れて検索する

1. 「入力元」は **「GCS から検索」** のまま（手元の mcap を処理したい場合のみ
   「ローカルの mcap」→ [6-3](#6-3-ローカルの-mcap-を-csv-化する)）
2. **車両ID**（例: `GIGA09`）と、**開始日付・開始時刻、終了日付・終了時刻**を入力
   - 時刻は `20:40` / `20:40:15` / `204015` のどの書き方でも OK
   - **日付をまたぐ実験**は終了日付を翌日以降にすればそのまま指定できます。
     終了日付が開始と同じで終了時刻が開始より前の場合は、自動で「翌日扱い」になります
   - 24 時間を超える範囲も指定できますが、対象ファイル数・処理時間・費用が大きく
     なりやすいので、② の合計サイズを確認してから進んでください
   - **まずは 1〜5 分程度の短い時間帯で試す**のがおすすめ（速く・安く動作確認できる）
3. チェックボックス 2 つを確認:
   - **record_debug_image も含める**（既定オン）… CSV だけが目的なら**オフでよい**
     （image は CSV には使われません）
   - **record_sensor も含める**（既定オフ）… EPS 等、**sensor 側にしか入っていない
     トピック**が欲しいときだけオン（→ [9-4](#9-4-抽出結果が-0-行空になる)）
4. **「🔍 ① 候補ファイルを検索」** を押す

しばらく待つと、該当する mcap ファイルの一覧が出ます。
この検索で読み込むのはメタデータだけなので課金はほぼゼロです。

### ② 対象ファイルを確認する

見つかったファイルが 1 行 1 ファイルの表で表示されます
（種類 develop/image/sensor・時間帯・サイズ付き）。基本は**全部選択されたままで OK** です。

外したいファイルがある場合は、行をクリックして選択し（Shift+クリックで範囲選択）、
表の下の「含める / 外す / 入替」ボタンで「抽出」列を切り替えます。
「develop のみ」などの一括ボタンもあります。

> 💡 ここで選んだ**ファイルの合計サイズ**が、直接ダウンロードした場合の課金額を決めます
> （表の下に選択中の合計サイズが出ます）。VM 経由なら気にしなくて構いません。

### ③ トピックを選ぶ

1. **「📋 トピック一覧を取得」** を押す → データに実際に入っているトピックが
   メッセージ数・エンコード付きの表で出ます
2. 欲しいトピックの「選択」列にチェックを入れる。楽な方法:
   - **プリセット**のプルダウンから選ぶ（「走行解析」「知覚系」など。
     `mcap_presets.json` を編集すれば自作プリセットも追加できます）
   - **「全トピック選択」** にチェック（とりあえず全部欲しいとき）
3. （任意）**カラム絞り込み・列名変更**: 「🧩 カラム絞り込み・列名変更」を開いて
   「カラム一覧を取得」を押すと、トピックごとに CSV へ出力する列を選べます。
   不要な列を × で外すと CSV が小さく見やすくなります
   （VM 経由の場合は回収する CSV が小さくなる＝課金もわずかに下がります）。
   その下の**「✏ 列名の変更」**では、出力 CSV のヘッダを客先向けの分かりやすい
   名前（例: `speed` → `車速[km/h]`）に変えられます。設定 JSON に保存されるので、
   一度作れば車両や日時を変えても同じ列名で出力できます

### ④ 出力する（VM 経由・推奨）

1. 出力形式: **「CSV (トピック別)」** を選ぶ
2. 出力フォルダを確認（既定は `out`）。
   全トピックを 1 本に結合した CSV も欲しければ「結合 CSV も出力」にチェックし、
   **結合 CSV の形式**を選ぶ:
   - **時間軸をそろえる（推奨）** … 一定周期（既定 100ms）の時刻グリッドに全トピックを
     並べ、各セルに「その時刻までの最新値」を入れる（前値ホールド）。周波数が異なる
     トピックを混ぜても歯抜けにならず、**そのまま Excel 等でグラフ化できる**ため、
     解析・図示用や社外提供用はこちら。列名は「トピック.列名」。
     「前値保持の上限」（既定 5 秒）を超えて更新が無い区間は空欄になり、
     本当のデータ欠損が古い値で埋まって見えることを防ぐ
   - **メッセージ到着順（従来形式）** … 1 メッセージ 1 行で時刻順に並べる。
     他トピックの列は空欄になるため、周波数が違うトピックを混ぜると歯抜けに見える

   また、**「⏳ 分割出力」**に分数（例: 30）を入れると、指定期間を 30 分ごとに
   区切ってファイルを出力できます（12:00-12:30, 12:30-13:00, ...）。数時間分の
   抽出でも 1 ファイルが巨大にならず、mcap の読み込みは 1 回のままなので
   追加の時間・課金はほぼかかりません
3. **CSV の抽出ルート: 「🌐 VM 経由（課金最小・推奨）」** を選ぶ
   - 「節約見込み ≈ ¥○○」と表示されます（直接ダウンロードした場合にかかったはずの金額）
   - **VM 運用**は「B: 毎回作って消す（待機費 ¥0）」のままで OK
   - **「認証を VM に入れる」** はチェックのまま（新規 VM では必須）
4. **「🚀 ④ 抽出実行」** を押す

あとは自動です。「① VM 作成ログ」「② 抽出・CSV 回収ログ」の 2 つのパネルに
進行状況が流れます。**全体で 5〜15 分程度**（VM 作成 2〜3 分 + 抽出本体）。
完了すると「完了: このランで CSV ○ 件を取得しました」と、生成された CSV の
一覧が表示されます。出力フォルダ（既定 `out/`）を開いて確認してください。

失敗した場合は → [9-3](#9-3-vm-経由の抽出が途中で失敗する) /
[9-4](#9-4-抽出結果が-0-行空になる)。

> 💡 **「💻 この PC で直接」ルートについて**: mcap を丸ごとダウンロードして手元で
> 変換します。すぐ始まりますが、選択ファイルの合計サイズ分の課金
> （約 18 円/GB）がかかります。ごく短い時間帯・少ないファイルのときや、
> 同じファイルを何度も使う（2 回目以降はローカルキャッシュが効いて課金ゼロ）
> 場合の選択肢です。

### 実行後の確認（任意・安心用）

VM は自動で削除されますが、心配なら ④ の **「🔍 課金状況を確認」** ボタンを押すと、
VM が残っていないかを確認できます。何も残っていなければ課金は発生しません。

### 複数の車両・期間をまとめて抽出する（⑤ バッチ実行・任意）

「同じトピック・出力設定で、複数の日付や車両のデータを夜のうちに全部取りたい」
ときは、④の下の **「⑤ バッチ実行」** を使います。

1. 通常どおり ①〜④ を設定する（③のトピック・カラム・列名変更と④の出力設定が
   バッチの全行に適用されます）
2. ⑤ の表に「車両ID / 開始日時 / 終了日時」を 1 行 1 抽出で並べる
   - 1 行目には**①の検索条件が自動で入っています**
   - **「➕ ①の検索条件を行として追加」**を押すと、①の内容が行として追加されます。
     ①の日時を書き換えてはこのボタンを押す、を繰り返すのが楽です
   - 表に直接入力しても OK（日時は `2026-08-18 12:00` の形式。行は表の下端で追加）
3. 「🌙 バッチ実行」を押す → 上から順に自動で抽出されます

補足:

- 対象ファイルは各行の条件から**自動で**絞り込まれます（②の手動選択は使いません）
- VM 経由の場合、VM は**バッチ全体で 1 台を使い回し、終了時に自動削除**されます
  （1 件ごとに作り直さないので速い）。途中で失敗した行はスキップして次へ進み、
  最後に成功/失敗の一覧が表示されます
- **夜間実行の注意**: 実行中はブラウザ画面を操作しない・**PC がスリープしない設定**
  にしておく（Windows: 設定 → システム → 電源で「スリープ: なし」）
- バッチの行も設定 JSON に保存されるので、毎晩同じセットを回すのも簡単です

### 条件の保存と再利用（任意・おすすめ）

ページ最上部の **「💾 設定の保存・読み込み」** を開くと、いま画面に入っている条件
（① の検索条件、② のファイル選択、③ のトピック・カラム選択、④ の出力設定）を
**JSON 1 ファイルとして保存**できます（「現在の設定を保存」→ ブラウザの
ダウンロードフォルダに保存されます）。

読み込むときは同じ場所で JSON ファイルを選んで「この設定を適用」を押し、
あとは通常どおり「候補ファイルを検索」→「トピック一覧を取得」と進むだけで、
保存しておいたファイル選択・トピック選択が自動で反映されます
（保存時と検索結果が変わっていて存在しないものは、その旨が表示されて無視されます）。

こんなときに便利です:

- **作り込んだ条件のバックアップ**: UI を再起動すると画面の条件は消えるため、
  トピックやカラムを細かく選んだら保存しておくと安心
- **定期的な抽出**: 同じ条件で日付・時間帯だけ変えて繰り返し取る
- **条件の共有**: JSON を渡せば、他の人が同じ条件をそのまま再現できる

## 6. CSV 以外の出力（mcap のまま欲しいとき）

④ の「出力形式」で選べます。どちらも「この PC で直接」のみ（ダウンロード課金あり）。

### 6-1. mcap（時間帯クロップ + トピック絞り込み）

指定時間帯・指定トピックのメッセージだけを 1 本の mcap にコピーします。
デコードしないので速く、Foxglove 等でそのまま開けます。③ でトピック選択が必要です。

### 6-2. mcap（元ファイルをそのまま保存）

② で選んだ mcap ファイル（1 分刻み）をそのままダウンロードします。
トピック選択は不要です。サイズが大きいので課金額の表示に注意してください。

### 6-3. ローカルの mcap を CSV 化する

すでに手元にある mcap を処理する場合は、① の「入力元」で **「ローカルの mcap」** を
選び、フォルダまたは glob パターン（例: `C:\data\*.mcap`）を指定します。
以降の手順（②③④）は同じで、GCS 課金は一切かかりません。
「時間帯で絞り込む」をオフにするとファイル全体が対象になります。

## 7. 2 回目以降のクイックリファレンス

セットアップ済みなら、毎回やることはこれだけです:

1. `start_ui.bat` をダブルクリック
2. ① 車両ID・開始/終了の日付と時刻を入力 →「候補ファイルを検索」
   （CSV だけなら「record_debug_image も含める」はオフ）
3. ② ファイル一覧を確認（基本そのまま）
4. ③ 「トピック一覧を取得」→ プリセントまたはチェックで選択
5. ④ 「CSV」+「VM 経由」+ VM 運用 B のまま「抽出実行」→ 完了まで触らず待つ
6. `out/` フォルダの CSV を回収

たまにやること:

- **条件の保存・読み込み**: ページ最上部の「💾 設定の保存・読み込み」で、作り込んだ
  条件を JSON に保存し、次回はそれを読み込んで検索するだけで再現できる
- **zero-plotter の更新**（月 1 回程度、または 0 行トラブル時）:
  `cd zero-plotter && git pull`
- **ローカルキャッシュの掃除**: ① の「詳細オプション」内で現在サイズの確認とクリアが可能
  （上限 20GB を超えると自動で古いものから消えるので、放置でも問題ありません）

## 8. コマンドラインで使う（上級者向け・任意）

UI を使わず CLI でも同じことができます。詳細は [README.md](../README.md) を

```bash
# 対象ファイルの確認だけ（ダウンロードなし）

# 含まれるトピックの確認
```

VM 運用の詳細（モデル A/B、Spot、コスト内訳、既存 VM への相乗り）は

## 9. トラブルシューティング

### 9-1. セットアップ・起動まわり

| 症状 | 対処 |
|------|------|
| `install_deps.bat` で「Python が見つかりません」 | Python をインストール。インストーラで「Add python.exe to PATH」にチェックを入れる |
| `pip install` が `mcap-ros2idl-support` の行で失敗 | private リポジトリの認証の問題。[3-3](#3-3-zero-plotterデコード用パッケージを用意する) の手動インストールで解決 |
| `.ps1` スクリプトが「実行できない」と言われる | PowerShell で一度だけ `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` を実行 |
| UI がブラウザで開かない | コンソールに出ている URL（`http://localhost:8501` 等）を手動でブラウザに入力（Linux / WSL では自動で開かないことが多い） |
| 起動時に `FutureWarning`（Python バージョンのサポート予告）や `UserWarning: ... without a quota project` が出る | **エラーではなく警告で、対応不要**。ログに `You can now view your Streamlit app in your browser` が出ていれば UI は正常に起動しているので、そのままブラウザで URL を開く。quota project の警告を消したい場合のみ `gcloud auth application-default set-quota-project t2-integration` を実行（任意） |
| 画面は表示されるが「候補ファイルを検索」等のボタンを押しても何も起きない | ボタンを押した直後に、**起動したターミナルに `[ui] 検索開始: ...` が出るか**を見る。**(a) 出る場合**: クリックは届いており処理中か失敗。ターミナルのエラーメッセージを確認し、該当する項目（認証は 9-2、0 件は 9-4）を見る。**(b) 出ない場合**: ブラウザとサーバーの通信（WebSocket）が切れている。SSH・VS Code のポート転送やリモートデスクトップ越しで起きやすい。まずページを再読み込み（F5）し、ダメなら開始時刻欄に `abc` と入れてみる（赤いエラーが出れば通信は正常）。リモートの場合はアプリを動かしている PC 自身のブラウザで開くか、`streamlit run app.py --server.address=0.0.0.0` で起動して表示される Network URL を開く |
| UI で「scripts/gcp.env が未設定のため VM 経由は使えません」 | [3-5](#3-5-vm-経由ルートの設定ファイルを作る) を実施。特に `GCP_VM` が `your-vm-name` のまま（または古い gcp.env で `GCP_PROJECT` が `your-project-id` のまま）だと使えない |

### 9-2. 権限がない系のエラー

| 症状 | 対処 |
|------|------|
| VM 作成時に `Reauthentication failed. cannot prompt during non-interactive execution` | 手元 gcloud の**ログイン期限切れ**（日をまたぐと切れる。正常な動作）。UI が自動で再ログイン画面を開くので、ブラウザで会社アカウントにログインすればそのまま続行される。画面が開かない場合は PowerShell で `gcloud auth login` を実行してから再実行 |
| 検索時に認証エラー | `gcloud auth application-default login` を実行し直す |
| 検索時に 403（バケットが読めない） | 自分のアカウントに `t2-ft-original-data` の読み取り権限がない。GCP 管理者に「バケット t2-ft-original-data の読み取り権限（roles/storage.objectViewer）を付与してほしい」と依頼 |
| VM 作成が `PERMISSION_DENIED` | `t2-integration`（gcp.env の `GCP_PROJECT`）で VM を作る権限がない。①管理者に「t2-integration での Compute Engine 利用（roles/compute.instanceAdmin.v1）の付与」を依頼（標準運用に揃うのでおすすめ）、または ②`GCP_PROJECT` を権限のある別プロジェクト（例: `t2-remote-devbox`）に変える |
| VM での抽出時に `403 ... does not have storage.objects.list access` | VM に自分の認証が入っていない。④ の「認証を VM に入れる」にチェックして再実行（CLI なら `-SetupAuth`） |

### 9-3. VM 経由の抽出が途中で失敗する

| 症状 | 対処 |
|------|------|
| ログ末尾が `Remote side unexpectedly closed network connection` 等で切れて失敗 | **Spot VM の中断**（`SPOT=1` 使用時の典型）。害はないので**もう一度「抽出実行」を押すだけ**で通常は成功する。頻発する場合は `scripts/gcp.env` の `SPOT=1` をコメントアウト |
| 初回 SSH で `Connection refused` がしばらく続く | VM 起動直後は SSH がまだ準備中。スクリプトが自動でリトライするので**待てば OK**（数十秒〜1 分） |
| VM 作成が `already exists` で失敗 | 同名の VM が既に存在している。**UI からの実行では起きなくなった**（実行時に VM の有無を自動判定し、既存 VM は作成せずそのまま使う。終了時は「VM 運用」に従い、**B なら削除（維持費ゼロを保証）**・A なら停止する）。`gcp_create_vm` を手で実行した場合はスクリプトが対処コマンド（マシンタイプ変更 or 削除）を表示するのでそれに従う |
| VM 作成に失敗した | 「① VM 作成ログ」を確認。権限エラーなら [9-2](#9-2-権限がない系のエラー)。一時的なエラーなら再実行 |
| ログに `[Errno 28] No space left on device` が並び、一部ファイルが読み込み失敗 | VM の一時ディスク不足。並列ダウンロードは並列数ぶんの一時ファイルを同時に持つため、record_sensor（1 本 2〜3GB）を高並列で読むにはディスクが必要（新しい既定は 200GB。昔の既定 30GB で作った VM で起きる）。**ツールは空き容量に合わせて並列を自動制限する**ので失敗はしなくなるが、並列をフルに効かせたい場合はディスクを拡張する: `gcloud compute disks resize <VM名> --size=200GB --zone asia-northeast1-a --project t2-integration` → VM を stop→start（拡張は VM 停止不要・縮小は不可）。**この警告が出た回の CSV はデータが欠けている可能性がある**ので、拡張後に該当区間を再実行して作り直すこと |
| 失敗後、VM が残って課金されていないか不安 | ④ の「🔍 課金状況を確認」ボタン（CLI: `scripts/gcp_status.ps1`）。VM 名の行が出なければ課金ゼロ。残っていたら表示される削除コマンドで消す |

### 9-4. 抽出結果が 0 行・空になる

| 症状 | 対処 |
|------|------|
| ログに `Unknown schema encoding: apex_json` があり、`/t2/main_mabx/*` や `/t2/control/demand*` だけ 0 行 | 手元の zero-plotter が古い。`cd zero-plotter && git pull` で更新（yatagarasu/main）してから再実行 |
| ログに `[warn] mcap-ros2idl-support が未インストール` があり、`/t2/*` が全部空 | [3-3](#3-3-zero-plotterデコード用パッケージを用意する) を実施。VM 経由の場合は `gcp.env` の `ROS2IDL_LOCAL_PATH` が正しいか確認 |
| 特定トピックだけ「トピック一覧には出るのに 0 行」 | そのトピックの**実データが別ファイルに入っている**可能性。EPS など sensor 系トピックは `record_sensor` 側に入っている（develop 側には名前だけ登録され中身がないことがある）。① で「record_sensor も含める」をオンにして検索からやり直す |
| 「対象トピックのメッセージが 1 件も見つかりませんでした」 | ③ でトピックを選び直す（CLI の場合は `--list-topics` で実トピック名を確認して設定 JSON を修正） |
| 時間帯は合っているはずなのにファイルが見つからない | ディレクトリの日付は**運行終了日**なので夜間走行は翌日付に入るが、これはツールが自動で考慮する。車両ID の綴り（例: `GIGA09`）と日付を再確認。それでも出ない場合は「セッション遡り時間」（詳細オプション、既定 24h）を増やす |

### 9-5. 動作が遅い・重い

**VM 経由の抽出が遅い場合**(数分〜十数分かかる):

- 時間の大半は **VM 上での mcap ダウンロード+デコード**です。特に `record_sensor` は
  1 分あたり約 2.6GB あるので、sensor 込み 30 分の抽出は約 90GB を処理しています。
  sensor 側のトピックが不要なら①のチェックを外すのが最も効きます
- VM の既定は **e2-highcpu-32（並列 31）・ディスク 200GB** になっており、通常は
  そのままで最速です。昔の既定（e2-standard-8 / 30GB）で作った VM を使い回している
  場合は、一度削除して作り直すと速くなります
- 冒頭のツール転送(30 秒〜1 分)は、⑤バッチ実行なら 2 件目以降で自動スキップされます

**①「候補ファイルを検索」が遅い場合**:

- 検索は「対象になりうる mcap の時刻メタデータを PC からインターネット越しに読む」
  処理で、候補が多い日（セッション数が多い日）ほど時間がかかります。打ち手:
  - 詳細オプションの**「メタデータ並列数」を 32〜64 に上げる**（ネットワーク待ちが
    支配的なので並列を上げた分ほぼそのまま速くなる。既定を 32 に引き上げ済み）
  - 詳細オプションの**「セッション遡り時間」を実態に合わせて短くする**（既定 24h。
    1 セッションが数時間以内の運用なら 6h 程度で十分で、候補ファイル数が減る。
    ただし長時間連続のセッションがある日は取りこぼしに注意）
  - ⑤バッチ実行なら検索は VM 側（GCS と同一リージョンで低遅延）で行われるため、
    手元の①検索は代表 1 回だけで済ませ、残りはバッチに任せるのも手

**この PC で直接・共通の対策**:

- **不要な重量級トピックを外す**のが最も効きます。生パケット系・TF・イベント系は
  行数が桁違いに多い:
  - UI: ③ でそれらのトピックのチェックを外す
  - CLI: `--exclude-topics "/t2/positioning_driver/internal/*" "/tf*" "/events/*"`
- 抽出時間帯を短くする、② で対象ファイルを減らす（特に sensor はサイズ大）
- 「この PC で直接」ルートなら ① 詳細オプションの「抽出並列数」を CPU コア数まで
  上げる（メモリ使用量も増える点に注意)

### 9-6. 課金についての FAQ

- **検索やトピック一覧だけで課金される?** → 読むのはメタデータ数 MB のみ。1 円未満です。
- **VM 経由 1 回あたりの費用は?** → 合計 ¥5〜10 程度（VM 稼働費 + CSV 数 MB の転送）。
  使い終わると VM ごと削除されるので、**使っていない間の課金は完全にゼロ**です。
- **トピックを絞れば直接ダウンロードは安くなる?** → なりません。mcap は全トピック混在の
  圧縮ブロック形式のため、絞ってもダウンロード量はほぼ変わりません。安くしたいなら
  VM 経由を使うか、② でファイル自体を減らしてください（image・sensor を外す等）。
- **同じデータをもう一度抽出したら?** → 「この PC で直接」の場合、一度ダウンロードした
  mcap は `mcap_cache/` に保存され、2 回目以降は課金ゼロで動きます（既定で有効・上限 20GB）。
- **どれだけ課金されたか知りたい** → 実行のたびに UI に「GCS 読み込み量と概算費用」が
  表示されます。
